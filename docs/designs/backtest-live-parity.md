## Premises

Confirmed with the owner during the session.

1. **This is a cold restart, not a continuation.** Five months idle, uncommitted work in
   the tree, no recall of system state.

2. **The 0% stop-loss rate is a measurement bug, not a result.**
   `true_backtest.py:661` filters `cikis_neden == "SL"`. The string `"SL"` is never
   assigned anywhere in the file. `cikis_neden` takes only `"SÜRE"` (line 403) and
   `"TRAIL"` (lines 425, 443). `sl_is` is always `[]`; `sl_oran` is always `0.0`.
   Verified present in committed V5 as well (`git show HEAD:true_backtest.py`), so the
   README's V1 66.1% / V3 62.8% / V5 0.0% comparison contrasts two measured numbers
   against one that is structurally incapable of being non-zero.

3. **Only live evidence is 3 fills and a 1.6% drawdown.** Sample too small to conclude;
   sign is negative.

4. **The backtest does not describe the system that trades.** Eight divergences, below.

5. **The Reg T reasoning was right, its application was wrong.** `SHORT_IZIN_ESIK = 2100.0`
   correctly encodes the $2,000 short-selling minimum with a buffer. It is compared
   against an account holding $98,418, so it evaluates `True` unconditionally. The
   previous code blocked every SHORT without exception. **This change reads as adding a
   safety rail and in fact removes one.** Five FXY shorts currently sitting blocked in
   `order_log.json` would execute on the next run.

## Fill Realism (added 2026-08-30, decision D22)

**Surfaced by external research, not by the review itself.** The owner supplied
https://pinggy.io/blog/best_ai_trading_agents/ which frames the backtest-to-live gap
(15–40bps per round trip) as the central problem in quantitative finance. Grepping this
repo for cost modelling returns nothing.

Alpaca is commission-free on US equities, so commission is genuinely near zero. The
repo-specific defect is worse:

```python
# islem_simule, LONG branch
if low <= trail_stop:          # tests whether the day's LOW reached the stop
    cikis_fiyat  = trail_stop  # books the fill AT the stop price
```

A bar that gaps down and opens 8% below the stop still satisfies `low <= trail_stop`, and
the exit is credited at `trail_stop`. Real stop orders become market orders and fill near
the open. **V5 removed fixed take-profit entirely, so 100% of price-driven exits are stop
exits** — the optimism applies to essentially every losing trade, on a watchlist
(MSTR, ASTS, PLTR, TSLA, IBIT) where overnight gaps are normal behaviour.

This is the third of three defects all biasing losses downward:

| Defect | Effect on reported results |
|---|---|
| `"SL"` never assigned (Premise 2) | Stop-outs invisible, reported as 0% |
| Fill booked at stop price | Stop-outs cheaper than achievable |
| No entry slippage | Entries free |

**Decision D22:** model gap-through — fill at `min(stop, bar_open)` for LONG,
`max(stop, bar_open)` for SHORT. Uses the `Open` column already in the dataframe.
Task T23, P1.

## Approaches Considered

### Approach A: Fix the three lying numbers in place
Assign `"SL"` at the true stop condition, add a SPY buy-and-hold line, surface the 15%
live cap in backtest output. Effort S (human ~2h / CC ~15min). Risk Low.
Rejected as insufficient: fixes 3 of 8 divergences, and nothing prevents new ones.

### Approach B: Shared config module + CI parity test  ← SELECTED
Extract every risk/sizing/threshold constant into one module that both `true_backtest.py`
and the live path import. Add a test that fails CI when the two disagree on weights,
sizing, thresholds, or SHORT rules. Apply A's fixes on top. Effort L (human ~2 days /
CC ~1.5h). Risk Med.

### Approach C: Replay harness through the live decision path
Feed historical bars through the real `state_manager` decision function and real
`alpaca_trader` sizing against a mock broker, so the backtest drives live code rather
than imitating it. Effort XL (human ~1 week / CC ~4h). Risk High.
Rejected as first move, retained as destination: refactoring order-placing code while
cold on the codebase is where serious bugs originate. Revisit after B lands.

## Recommended Approach

**Approach B.** It contains every fix in A and adds the one artifact that defends itself
across long absences. The owner's own history is the argument: this codebase has already
demonstrated it can lose five months of context, and a parity test is the only proposed
output that is still doing its job when that happens again.

C is the correct destination. It is the second move.

## Success Criteria

1. `cikis_neden` distinguishes a stop hit before the watermark moved from a profitable
   trail-out. The reported SL rate is a measured number.
2. Backtest report prints SPY buy-and-hold return and Sharpe over the identical window.
3. One config module is the single source for thresholds, weights, position caps, and
   SHORT eligibility. Both paths import it.
4. A CI test fails on any backtest/live divergence across those four dimensions.
5. `quant_math.py` is added to the CI `py_compile` list. It currently is not, despite
   holding all V6 math.
6. Either `kelly_gecmis.json` gets a writer, or `kelly_pozisyon_al` is deleted and the
   README claim withdrawn. Silent permanent fallback is not acceptable in sizing code.

## Open Questions

- Which value is canonical for each divergent constant? Live 15% cap or backtest 35%?
  This is a genuine risk-appetite decision, not a merge conflict.
- Should `AGIRLIK_INSIDER` and `AGIRLIK_GAMMA` be renormalised out of the backtest score,
  or should the backtest synthesise historical insider/gamma inputs? Renormalising is
  cheap and honest; synthesising is expensive and probably infeasible.
- Does the Claude veto belong in the hot path at all? It is currently a critical-step
  dependency with no test, and any API error silently converts every signal to HOLD.
